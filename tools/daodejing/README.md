# 道德经数据的构建流程

`data/daodejing.json` 不是手写的，是由这个目录下的脚本生成的。发现注音或文字有误，改源头再重跑，别直接改生成结果——下次重跑会被覆盖。

## 跑一遍

```bash
pip install pypinyin
cd tools/daodejing
python3 split.py          # raw.txt → chapters.json，校验 81 章连续
python3 pinyin_build.py   # 生成拼音，叠加 fixes.json 的修正
python3 build.py          # 合并 meta，校验，输出 daodejing.json
cp daodejing.json ../../data/
cd ../.. && node _selftest.js
```

## 各文件是什么

| 文件 | 作用 |
|---|---|
| `raw.txt` | **底本**。一行一章，`第N章 正文`。异体标点已规范为全角标准符号 |
| `fixes.json` | **多音字修正表**。pypinyin 按今音注，这里列出古读该改的词组 |
| `meta1/2.json` | 每章的 `title`（章题）、`key`（摘句）、`explain`（白话） |
| `split.py` | 切章 + 校验章号连续 |
| `pinyin_build.py` | 注音 + 应用修正表 |
| `build.py` | 合并 + 校验 + 输出 |

## 改注音

打开 `fixes.json` 加一行，key 是原文里出现的词组，value 是拼音（空格分隔）：

```json
"多言数穷": "duō yán shuò qióng"
```

**音节数必须等于汉字数**，否则 `pinyin_build.py` 会直接报错退出。改完重跑上面三步。

脚本会报告修正表里有哪些词组在原文中一次都没命中——那通常意味着词写错了。

## 校验都查什么

`build.py` 和 `_selftest.js` 会卡住这些：

- 章号必须是 1–81 连续
- 每章 `title`/`text`/`pinyin`/`explain`/`key` 都不能空
- **摘句必须是本章原文的子串**——防止组件上显示一句书里没有的话
- **拼音音节数必须逐章等于汉字数**——防止漏字或多字
- 全书字数应在 5000–5600 之间（传统称「五千言」，实测 5267）

## 底本说明

原文是用户提供的通行本，**未作校改**。它与王弼本在若干处有异文，例如：

| 章 | 本底本 | 王弼本 |
|---|---|---|
| 八 | 正善治 | 政善治 |
| 十 | 爱国治民 | 爱民治国 |
| 十五 | 故能蔽不新成 | 故能蔽而新成 |
| 十七 | 大上，下知有之 | 太上，下知有之 |
| 二十一 | 自今及古 | 自古及今 |
| 五十三 | 是为夸盗 | 是谓盗夸 |
| 七十六 | 木强则兵 | 木强则共／折 |

这些都是版本差异而非错字，保留原样。想换成王弼本，改 `raw.txt` 重跑即可。

白话解释是自撰的，没有抄录任何现成译本。
